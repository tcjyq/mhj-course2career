02Problem

课程经历，为什么难以直接回答岗位要求？

大学课程、项目与实习常以不同的语言记录；岗位 JD 则同时包含技能、职责和硬性条件。求职者难以判断已有经历能证明什么，也难以区分“能力差距”与“当前不满足的硬门槛”。

Course2Career 将这些输入组织成可复核的证据链：先结构化理解岗位，再由用户确认关键技能，最后由 Python 规则完成映射、评分和学习建议。

03How it works

从 JD 到下一步行动

AI 参与理解，用户确认关键输入，规则负责把结论算清楚。

  1. 01JD 输入粘贴岗位职责与要求
  2. 02LLM 结构化提取识别岗位技能与要求
  3. 03人工确认修订关键技能证据
  4. 04Python 确定性规则映射课程、项目与实习
  5. 05五维评估分开呈现适配与门槛
  6. 06能力差距识别可补齐的证据缺口
  7. 07学习路线按能力模块给出下一步
04Evidence

把判断过程留在页面上

不是把匹配度包装成录用概率，而是展示当前证据、限制和下一步。

01

五维评估

技术、教育、项目、实习与潜力分别呈现，避免只给出一个黑箱分数。

02

硬门槛独立判断

门槛状态单独展示；学历也参与教育维度。未设置门槛不能解释为已经满足。

03

Human-in-the-loop

岗位技能在进入评分前允许人工确认，保留对提取结果的判断权。

04

可复核的回归测试

历史公开 Demo 基础审计为 120 项通过。最新本地优化与验证记录见 GitHub docs/optimization-review.md；代码通过不等于业务效果已校准。

06My role

我的角色

以产品判断与可验证的实现协作为中心，不将 AI 协作开发表述为个人独立完成全部代码。

  • 01需求分析

    梳理课程经历、岗位要求与求职决策之间的输入和输出边界。

  • 02规则设计

    将硬门槛、能力证据、五维评估与学习路线拆分为可解释的规则。

  • 03结果验证

    通过测试、页面流程与结果限制检查，验证输出不被误读为录用预测。

  • 04AI 协作开发

    在 AI 协作下完成代码实现与迭代，并保留人工确认和结果核验。
