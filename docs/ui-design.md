# 界面与产品体验

## 设计目标

Course2Career保持单体Streamlit，不引入React、独立前端服务或复杂组件库。界面采用暖灰背景、深绿色操作色、细边框和编辑式排版，避免渐变、大面积品牌色、重阴影、夸张圆角和装饰性图标。

## 信息架构

```text
Course2Career
├── 开始
│   ├── 首页
│   └── 登录
├── 工作台
│   ├── 个人分析
│   └── AI额度
├── 账户
│   ├── 会员升级
│   └── 开发者API Key
└── 管理
    └── 管理员Dashboard
```

管理员入口只对`admin + Admin`显示。开发者Key页面对所有用户可见，但只有Developer和Admin套餐能够进入管理功能，其他用户看到明确的升级说明。页面可见性只改善体验，最终权限仍由服务层验证。

## 页面职责

- 首页：岗位适配度定位、输出内容和四步使用流程。
- 登录：登录、注册以及已登录账户状态。
- 个人分析：课程导入、候选人资料、JD技能确认、硬门槛、五维适配度、解释账本和能力路线。
- AI额度：展示今日使用、每日上限、剩余额度和自带Key说明。
- 会员升级：展示套餐差异和升级演示，不创建订单或改变套餐。
- 开发者API Key：查看末四位、加密保存、更新和删除。
- 管理员Dashboard：系统概况、AI成本和用户套餐管理。

## 交互原则

- 每页只保留一个主要任务。
- 使用有边框容器分隔流程，不依赖颜色表达状态。
- 表单提交后显示明确成功或错误信息。
- 空记录、无Key、未登录和无权限都有可读状态。
- 本地规则模式始终可用，并明确不消耗AI额度。
- 导航和身份状态在所有页面保持一致。
- “暂未填写”和“目前没有”使用明确选项，不允许系统擅自补全个人经历。
- 硬门槛、适配度、数据完整度和可信度并列展示，不合并为录用概率。
- 加减分使用带符号数值和文字原因，不只依赖颜色表达好坏。
- 学习建议按能力模块分组，避免长列表造成信息过载。

## 历史报告交互

“个人分析”页面底部仅在登录后显示“最近分析”。用户可选择一份历史记录并点击“重新打开这份报告”；恢复后报告回到结果区域，并显示不会回填课程文件和 JD 的说明。

## 视觉规则

- 画布：暖灰`#F7F6F3`。
- 主文字：炭黑`#252A27`。
- 主操作色：深绿`#243F37`。
- 分隔线：浅灰`#E4E3DE`。
- 卡片最大圆角8px，不使用重阴影和渐变。
- 标题使用系统可用的编辑式衬线字体，正文使用系统无衬线字体。

主题基础变量位于`.streamlit/config.toml`，少量布局样式位于`ui/styles.py`。

## 测试

- 页面组件通过Streamlit AppTest分别验证。
- 首页验证默认落点和信息层级。
- 个人分析验证Excel导入、错误状态、候选人资料、技能迁移、硬门槛和完整本地分析。
- 登录、额度、会员、开发者和管理员页面均有渲染测试。
- Streamlit真实服务健康检查必须返回`ok`。
