# Course2Career 产品需求

## 1. 用户故事与范围

作为大学生，我希望输入课程、教育背景、项目、实习、成长条件和目标岗位 JD，获得硬门槛检查、可解释岗位适配度、能力差距和可执行的学习建议。

当前版本包含课程导入、候选人资料、JD技能提取与人工确认、课程技能映射、技能迁移、五维适配度、硬门槛检查、解释账本、能力模块路线和报告导出。产品化能力包括SQLite账号、角色权限、AI日额度和登录用户分析历史。不包含招聘网站爬取、简历解析、向量数据库和录用概率预测。

## 2. 功能验收标准

### 课程导入

- 可下载包含“课程信息”和“填写说明”的 `.xlsx` 模板。
- 课程信息包含课程名称、学分、成绩、课程类别、自评掌握程度。
- 学分范围为 `(0, 20]`，成绩为 `[0, 100]`，自评为 1 到 5 的整数。
- 文件级错误阻止导入；行级错误单独展示，其他合法行继续参与分析。
- 完全空白行忽略，重复课程只保留首次合法记录。

### JD 分析

- 接受 20 到 12000 个字符的 JD。
- 本地规则模式无需外部服务；OpenAI 模式从环境变量读取配置。
- 输出岗位名称、规范技能、类别、重要程度和 JD 原文证据。
- 未提取到技能时阻止分析并给出可读提示。
- 用户可编辑或排除技能，至少保留一项后才能生成报告。

### 映射与评分

- 每条技能支撑证据可追溯到具体课程及命中的映射规则。
- 项目和实习中明确填写的技能可作为直接证据。
- 相邻技能可以按版本化规则有限迁移，迁移来源、目标和强度必须可解释。
- 缺少技能直接证据时保留大学生学习基础分，不得直接按零分处理。
- 岗位适配度包含技术技能、教育背景、项目实践、实习实践、学习与就业潜力五个维度。
- 展示五维评分、综合适配度、优势、缺口和逐项加减分原因。
- 最终分数必须能够由 `50 + 加减分账本` 准确还原。
- 评分由 Python 确定性计算，大模型不得直接决定分数。

### 候选人资料与硬门槛

- 教育资料包括学历、院校类型、专业和核心课程表现。
- 项目资料包括技能、相关性、完整度、技术深度、个人贡献、可验证性和迭代记录。
- 实习资料包括岗位、企业、技能、相关性、工作深度、成果、企业行业信号和时长。
- 成长资料包括学习距离、近期成长、求职准备、投入意愿和城市机会。
- 系统区分“暂未填写”和“目前没有”；未填写使用中性值并降低可信度。
- 最低学历、专业、毕业年份、每周到岗天数、连续实习时长和工作城市独立检查。
- 硬门槛结果不得与岗位适配度混成单一“录用概率”。

### 学习路线与导出

- 对支撑分低于 50 的相关技能生成最多 8 个能力模块。
- 每个模块包含关联缺口、能力目标和可验证成果。
- 可导出 Markdown 完整报告和带 UTF-8 BOM 的 CSV 技能明细。

### 用户权限

- 游客可以使用完整规则Demo，并拥有每天2次平台AI体验。
- 公开注册只能创建普通用户，密码只保存scrypt哈希。
- Free用户每天5次平台AI调用，可以保存和查看自己的分析历史。
- Pro用户每天20次平台AI调用，并预留高级报告权限。
- Developer用户可以加密保存并使用自己的API Key。
- Admin拥有系统状态和会员管理权限，不受平台AI日额度限制。
- 当前不实现支付、订单、订阅和用户自助升级。
- 管理员不受AI日额度限制，可以查看聚合系统状态。
- 权限检查发生在服务端应用层，不修改原有评分和分析逻辑。

### 历史报告恢复

- 登录用户可从“最近分析”重新打开自己的报告快照；按用户 ID 与记录 ID 同时查询，禁止跨账号读取。
- 历史选择以唯一报告 ID 为值；即使分析时间、岗位名称和分数完全相同，也不能合并或隐藏记录。
- 旧版 `AnalysisReport` 以明确标注的旧版界面恢复，不得按 v2.1 五维字段渲染或伪造新评分口径。
- 历史快照只恢复报告结果，不持久化或回填课程 Excel、完整 JD、密码和 API Key。

## 3. 非功能要求

- 不记录 API Key，不在错误信息中暴露供应商响应或完整敏感输入。
- 单元测试不访问网络，外部模型使用模拟客户端。
- 应用在未配置 API Key 时仍可通过本地规则完成全部主流程。
- 用户界面默认中文，源文件为 UTF-8。
- 岗位适配度必须明确标注“不代表录用概率”。
- 用户可见功能变化必须同步更新 README、使用说明、评分或架构文档及开发日志。
