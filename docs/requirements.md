# Course2Career 产品需求

## 1. 用户故事与范围

作为大学生，我希望输入课程、教育背景、项目、实习、成长条件和目标岗位 JD，获得硬门槛检查、可解释岗位适配度、能力差距和可执行的学习建议。

当前版本包含课程导入、候选人资料、JD技能提取与人工确认、课程技能映射、技能迁移、五维适配度、硬门槛检查、解释账本、能力模块路线和报告导出。产品化能力包括SQLite账号、角色权限、AI日额度和登录用户分析历史。不包含招聘网站爬取、简历解析、向量数据库和录用概率预测。

## 2. 功能验收标准

### 课程导入

- 可下载包含“课程信息”和“填写说明”的 `.xlsx` 模板。
- 课程信息包含课程名称、学分、成绩、课程类别、自评掌握程度。
- 学分范围为 `(0, 20]`，成绩为 `[0, 100]`，自评为 1 到 5 的整数。
- 文件级错误阻止导入；行级错误单独展示，其他合法行继续参与分析。
- 完全空白行忽略，重复课程只保留首次合法记录。

### JD 分析

- 接受 20 到 12000 个字符的 JD。
- 本地规则模式无需外部服务；OpenAI 模式从环境变量读取配置。
- 输出岗位名称、规范技能、类别、重要程度和 JD 原文证据。
- 未提取到技能时阻止分析并给出可读提示。
- 用户可编辑或排除技能，至少保留一项后才能生成报告。
- DeepSeek 默认采用 Auto-Safe：仅从官方目录中“当前可用且已通过应用验证”的模型选择。
- C08-B1 本地实现十家主流官方 Provider Preset + Developer/Admin BYOK：OpenAI、DeepSeek、百炼、OpenRouter、SiliconFlow、Moonshot/Kimi、Zhipu/GLM、MiniMax、Google Gemini、Anthropic Claude；按 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages、Gemini API 四类协议复用适配器。免费套餐系统 AI 只提供 DeepSeek；分析页只显示已配置 Key 且有模型 ID 的用户 Provider。用户 Key 使用 AES-256-GCM，BYOK 不消耗平台 system quota，端点只取受控官方 ID。新增模型仅有 fake 契约测试，真实兼容性待验证；价格未知不显示为免费。C08-D 才开放经 SSRF 防护的自定义 Provider。
- C08-C 官方模型目录优先显示大陆六家，国际四家折叠；动态 API 和短静态官方目录均记录来源与核对日期。官方 Structured Output、目录可用性和 Course2Career 真实验证分层，UNKNOWN 不当作 0 元或不支持。缓存按用户/端点/Workspace/Key 版本隔离，支持 TTL、手动刷新与失败旧目录；B3 关闭时禁止使用缓存。DeepSeek 旧名只提示主动迁移，不自动修改 Profile。[模型发现规范](c08-model-discovery.md)。
- C08-B2 将 `UNKNOWN`、`CONNECTED`、`SCHEMA_COMPATIBLE`、`VERIFIED`、`UNSUPPORTED` 限定为 Provider × 官方端点 × 精确模型状态。只有完整固定合成 JD 集、原文证据、usage 和返回模型均通过才能标 VERIFIED；单次连接测试最多标 Schema 兼容。Anthropic/Gemini 使用原生 schema 请求，百炼仅指定 Qwen 模型用 strict schema，DeepSeek 是 JSON object 加本地校验。当前真实请求仅 OpenAI 与 Anthropic，各一次 401，均未验证；详见 [B2 报告](c08-provider-validation.md)。
- 官方目录不可用时允许使用有效旧缓存或固定回退模型；未知模型不得自动上线。
- 主模型返回模型不存在错误时，最多尝试一个已验证备用模型；限流、鉴权和服务错误不得触发跨模型重试。

### 映射与评分

- 每条技能支撑证据可追溯到具体课程及命中的映射规则。
- 项目和实习中明确填写的技能可作为直接证据。
- 相邻技能可以按版本化规则有限迁移，迁移来源、目标和强度必须可解释。
- 缺少技能直接证据时保留大学生学习基础分，不得直接按零分处理。
- 岗位适配度包含技术技能、教育背景、项目实践、实习实践、学习与就业潜力五个维度。
- 展示五维评分、综合适配度、优势、缺口和逐项加减分原因。
- 最终分数必须能够由 `50 + 加减分账本` 准确还原。
- 评分由 Python 确定性计算，大模型不得直接决定分数。

### 候选人资料与硬门槛

- 教育资料包括学历、院校类型、专业和核心课程表现。
- 项目资料包括技能、相关性、完整度、技术深度、个人贡献、可验证性和迭代记录。
- 实习资料包括岗位、企业、技能、相关性、工作深度、成果、企业行业信号和时长。
- 成长资料包括学习距离、近期成长、求职准备、投入意愿和城市机会。
- 系统区分“暂未填写”和“目前没有”；未填写使用中性值并降低资料完整度。
- 最低学历、专业、毕业年份、每周到岗天数、连续实习时长和工作城市独立检查。
- 硬门槛结果不得与岗位适配度混成单一“录用概率”。

### 学习路线与导出

- 对支撑分低于 50 的相关技能生成最多 8 个能力模块。
- 每个模块包含关联缺口、能力目标和可验证成果。
- 可导出 Markdown 完整报告和带 UTF-8 BOM 的 CSV 技能明细。

### 用户权限

- 游客始终可以使用完整本地规则 Demo；平台已配置且启用 DeepSeek 凭证时，才显示免费套餐系统AI及其每天2次体验额度。
- 公开注册只能创建普通用户，密码只保存scrypt哈希。
- Free用户每天5次平台AI调用，可以保存和查看自己的分析历史。
- Pro用户每天20次平台AI调用，并预留高级报告权限。
- 普通登录用户可免费启用或关闭独立的开发者模式；启用后可加密保存并使用自己的 API Key，不改变 Role、Plan 或平台系统 AI 日额度。关闭后服务层拒绝新的 BYOK 配置和调用，但保留密文供重新开启后使用；Admin 和历史 Developer Role/Plan 保留访问能力。
- API Key 提交后必须立即清空输入控件和对应会话状态，页面不得回显完整密钥。
- Admin拥有系统状态和会员管理权限，不受平台AI日额度限制。
- 当前不实现支付、订单、订阅和 Free/Pro 用户自助升级；开发者模式开关不属于套餐升级。
- 管理员不受AI日额度限制，可以查看聚合系统状态。
- 权限检查发生在服务端应用层，不修改原有评分和分析逻辑。

### 历史报告恢复

- 登录用户可从“最近分析”重新打开自己的报告快照；按用户 ID 与记录 ID 同时查询，禁止跨账号读取。
- 历史选择以唯一报告 ID 为值；即使分析时间、岗位名称和分数完全相同，也不能合并或隐藏记录。
- 旧版 `AnalysisReport` 以明确标注的旧版界面恢复，不得按 v2.1 五维字段渲染或伪造新评分口径。
- 历史快照只恢复报告结果，不持久化或回填课程 Excel、完整 JD、密码和 API Key。

## 3. 非功能要求

- 不记录 API Key，不在错误信息中暴露供应商响应或完整敏感输入。
- 单元测试不访问网络，外部模型使用模拟客户端。
- 应用在未配置 API Key 时仍可通过本地规则完成全部主流程。
- 用户界面默认中文，源文件为 UTF-8。
- 岗位适配度必须明确标注“不代表录用概率”。
- 用户可见功能变化必须同步更新 README、使用说明、评分或架构文档及开发日志。
- 每次真实 DeepSeek 调用应记录最终模型 ID；模型目录缓存不得保存、展示或记录 API Key。
- 从侧边栏切换页面时，上一页面的内容必须被清理，不得与当前页面混合显示。
- 部署热更新期间，新版用量服务与缓存的旧仓储接口短暂共存时，不得影响已完成模型调用的状态、Token 和费用回写。
- 招聘 Showcase 必须是独立静态页面：不依赖 Python、Streamlit、数据库、API Key 或登录，首屏可直接加载；其在线体验入口可指向 Streamlit Live Demo，但不得将 Showcase 域名 302 重定向到 Streamlit。
- Showcase 只能使用仓库已有、可追溯的截图和事实，不得生成或冒充产品截图；它必须提供 Live Demo、GitHub 和 Portfolio 链接，并保持桌面端与移动端可浏览。

## 2026-09-21 求职方向优化验收

- 通用课程不推断具体语言或BI工具；材料明确、间接推断、迁移、自述、未体现可区分，多条来源保留。
- 只由填写情况决定的标签显示资料完整度，空门槛显示未设置／待确认。
- JD引用仅支持逐字或连续空白折叠核对；引用落点与技能含义分开；修正后重新检查。未定位项仍可按现有人工勾选契约纳入，并提示待确认；空引用需修正。
- 三个合成案例独立演示、下载输入、重置及导出；不覆盖个人资料。
- 学习任务含交付物与验收标准；兼容旧快照、旧CSV五列及旧学习路径；不更改无关权重。

## C08-D0 生产持久化要求

正式开发者 BYOK 的账号、鉴权、会话版本、开发者开关、加密 Key、Provider Profile、报告与用量必须同在持久 SQL 数据库；生产数据库失败时停用相关功能并显示安全错误，不回退临时 SQLite。模型缓存可丢失；项目 VERIFIED 只接受受控版本证据。完成 PostgreSQL 集成、备份恢复与至少 DeepSeek、百炼真实固定集验证前，不进入生产发布。详见 [持久化设计](c08-production-persistence.md)。
